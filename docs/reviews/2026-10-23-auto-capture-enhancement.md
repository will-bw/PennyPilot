# 自动捕获功能分析与增强

日期：2026-10-23（北京时间）。范围：现有 Android 工程中的支付通知、可选支付页面捕获、识别、去重、待确认、运行诊断与数据迁移。保留工作树中已有的 ChatGPT 接入与界面修改。

## 1. 问题拆解

“通知栏没有显示”至少包含三种不同原因，不能只增加解析正则来解决：

| 场景 | 原实现问题 | 本次处理 |
|---|---|---|
| 支付应用没有发布系统通知，只有支付成功页面 | NotificationListenerService 没有输入 | 可选无障碍页面捕获；由用户明确开启并在系统授权 |
| 支付通知存在，但后台监听断开 | 只有服务断开重连，缺少补查 | 重连时补查最近 10 分钟仍有效的通知；开机请求恢复已授权连接 |
| 账目已经捕获，但 PennyPilot 自身提醒被禁止或设为静默 | 将通知读取权限与通知显示权限混在一起 | 分开展示监听权限、连接状态、应用提醒及通知类别状态；提醒失败仍保留待确认账目 |
| 在美团、抖音内支付 | 原来只接收微信、支付宝两个包 | 增加美团、美团外卖、抖音、抖音极速版 |
| 同一支付同时出现平台凭证和付款工具凭证 | 只按系统事件键去重 | 持久化交易证据，强证据合并，弱证据关联待核对 |
| 已经手记/AI 补记，随后支付通知才到达 | 自动捕获不检查补记记录 | 相近时间、具体商户、金额、方向均一致时标疑似重复 |
| 原价、优惠、余额与实付同时出现 | 简单正则可能选错金额 | 优先明确实付，拒绝金额歧义及非法金额；无法解释的其他金额不猜测 |
| 普通聊天、广告、订单历史出现支付词 | 宽泛动作匹配有误记风险 | 通知来源标题限制；页面完成标题和金额结构校验；历史、评论、聊天等负例过滤 |

系统限制：通知监听只能获得系统实际交付的通知，不能补出从未发布或已经撤回的内容。页面读取需要授权和可访问的界面节点，也不能保证覆盖每个版本的支付应用。

## 2. 功能设计与实际实现

### 双入口、统一待确认流水

```text
支付通知 → 包名/通知结构过滤 → 本地解析 → 可选通知云解析 ┐
                                                         ├→ 分类 → 原子去重 → 待确认 → 提醒
支付页面 → 用户双重启用 → 可见节点/凭证结构 → 本地解析 ┘
```

- 通知捕获默认保持开启，保留用户已有通知云解析偏好（云解析默认关闭）。
- 页面捕获默认关闭，需要应用内同意和系统无障碍授权，支持随时暂停。
- 两种入口均保存为 `PENDING`，不直接进入已确认收支统计。
- 页面捕获不调用 LLM；只保存识别出的金额、方向、商户和可用订单证据，不保存整页文字。
- 无障碍服务只声明六个支持包，仅处理窗口变化事件；不监听键盘输入事件、不截图、不点击、不执行付款。
- 读取可见文字后在本机判断是否为支付结果。出现可见密码或可编辑输入控件时整页拒绝；隐藏节点和其他包的节点不读取。读取最多 250 个节点、深度 30 层、12,000 字符；超界整份拒绝，避免截掉尾部失败说明再误记。
- 页面事件采用有界合并队列：短暂合并重绘，写入期间的新事件仍触发后续读取。同一页面结果重复重绘不重复提交；独立支付或新订单可生成新身份。

支持包名统一定义在 `PaymentAppRegistry`：

| 应用 | 包名 |
|---|---|
| 微信 | `com.tencent.mm` |
| 支付宝 | `com.eg.android.AlipayGphone` |
| 美团 | `com.sankuai.meituan` |
| 美团外卖 | `com.sankuai.meituan.takeoutnew` |
| 抖音 | `com.ss.android.ugc.aweme` |
| 抖音极速版 | `com.ss.android.ugc.aweme.lite` |

### 识别规则

- 支持支付/付款/消费完成、收款到账、退款完成等结果；退款到账按收入保存。
- 支持金额标签、货币符号和值分散在不同可访问节点的情况。
- 明确实付优先于原价、订单金额、优惠、运费等；规范千分位和两位以内小数可识别。
- 负数、指数、畸形千分位、三位小数、超额、非人民币及无法判定的多金额内容拒绝。
- “收款方”“收款商户”属于付款凭证字段，不作为收入动作。
- 失败、处理中、待付款、退款申请、广告、聊天及历史详情不会生成新交易。
- 页面须含独立的完成标题和明确金额结构；仅一句“支付成功 ¥18.00”或没有货币/金额标签的裸数字不足以触发。
- 自定义规则仍可补充内置解析未识别的商户，但金额、方向必须与本地证据一致；不能绕过来源、非法金额或歧义过滤。
- 微信聊天通知不因包含支付用语就调用云解析。云端补充仅在用户启用、本地支付候选成立并且金额不含已知歧义时尝试，等待上限 8 秒；结果再次校验金额和方向。
- 退款不借用原订单号做强去重，避免同一订单两次相同金额的分次退款被吞掉；独立退款编号的命名空间留待后续适配。

### 分层去重

| 证据 | 动作 | 保留的边界 |
|---|---|---|
| 同一捕获事件身份 | 自动合并 | 跨进程仍生效 |
| 同应用族、可靠完整订单号、金额方向一致 | 自动合并 | 美团/外卖共域、抖音/极速版共域；支付工具与电商平台不共享订单域 |
| 15 秒内同通知 key、原始 `notification.when`、文本、金额、方向一致 | 合并为通知更新 | 时间窗锚定首次事件；缺失或改变原始时间时不据此合并 |
| 通知/页面或不同平台，120 秒内同具体商户、金额、方向 | 新建待确认并标 `duplicateOf` | 不凭弱证据删除交易；不同可靠订单不视为同一笔 |
| 相同页面重新进入或服务重启，没有订单号 | 满足近时商户证据则标疑似，否则保留 | 不用整段文本永久屏蔽未来交易 |
| 手记/AI 补记后迟到的自动捕获 | 同商户金额方向、时间 ±120 秒且原记录未忽略时标疑似 | 保留原记录的金额、备注、状态和账户 |
| 只有同金额，或商户只是“美团/支付宝”等平台名 | 不合并、不标疑似 | 连续同额消费不应因金额碰撞丢失 |

去重检查、交易写入和事件别名写入使用同一 Room 事务，避免两个入口并发穿透。原记录无论已确认还是已忽略，重放都不覆盖其状态。确认为重复时不重复计数或发提醒。

疑似重复在流水中提供“查看相近记录”“仍然记入”“重复，忽略”；系统提醒不提供一步“记入”，引导先核对。用户删除原记录时原子清空关联提示，捕获别名通过外键级联删除，防止永久屏蔽重新捕获。

## 3. 可靠性与可诊断性

- 通知完整正文按展开正文、Inbox 多行、普通正文顺序选择，跳过分组摘要；不把展开与折叠内容拼成两笔。
- 通知队列容量 64，并合并排队中完全相同事件；队列满会显示可理解的诊断，不无限创建协程。
- 通知捕获暂停前后的队列有代际检查，暂停期间不继续收集新通知。
- 设置页分别显示通知监听授权/连接、页面捕获授权/连接、PennyPilot 提醒可用性，并提供系统设置入口和重新连接。
- 今日捕获数量从数据库查询，包含通知与页面，返回设置前台会刷新；最近成功捕获和重复拦截数明确按本次进程展示。
- 没有近期支付不等于服务故障，不以“超过 24 小时无通知”判定异常。
- 无通知输出权限时，待确认记录正常入库；提醒可点击打开记录，锁屏展示使用私密可见性。
- 统计刷新失败不阻止已经保存账目的提醒；错误内容为固定短句，不输出原始页面或敏感异常。
- 捕获继续使用账本版本校验。备份恢复期间旧解析不得写入新账本，提醒发送前后再检查版本，避免恢复后重发旧交易提醒。

## 4. 数据升级与兼容

数据库 v4 升至 v5：

- `transactions.duplicate_of`：疑似重复关联。
- `capture_events`：事件键、关联交易 ID、来源、时间、通知更新身份、文本摘要、订单域/号、金额方向、商户标准化证据。
- 文本证据采用 SHA-256，不在证据表重复保存整页内容；订单号和商户证据用于本机匹配。
- 非破坏性迁移，不删除原账本，不覆盖用户解析规则。
- 备份快照包含捕获证据，恢复后仍能去重；v1/v2/v3/v4 旧库继续走迁移。
- 兼容 v4 不含正文摘要的旧事件键：原金额、方向、正文均一致时补齐证据，保留原状态。

## 5. 验证与实际覆盖边界

自动化验证涵盖：合成的六应用支付样本、拆行节点、实付/优惠、多金额、退款、普通聊天、评论、历史详情、密码/输入框、通知恢复时间窗、并发订单、独立同额订单、忽略回放、手记/AI补记、删除后重捕、数据库迁移及备份证据恢复。

最终执行：

```bash
./gradlew --offline :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease --max-workers=1 --console=plain
```

- 全部 **240 项测试通过**，0 失败、0 错误、0 跳过；其中捕获服务与支付解析相关 95 项。
- Lint：0 errors、28 warnings。其中 27 条为依赖/Gradle 版本提示，1 条是 `isAccessibilityTool` 在 API 31 以下会被忽略的兼容提示；低版本不存在该声明属性，服务仍按应用开关和包白名单限制。
- Debug APK 和 Release APK 构建成功；Release 当前未配置发布签名，交付可安装版本使用 Debug APK。
- 模拟器 `emulator-5580` 保留数据更新安装成功；检查“我的 → 自动捕获”的开关、未授权状态、披露弹窗、独立提醒权限和诊断区域，未发现文字截断或按钮遮挡。
- 模拟器保持页面捕获关闭，没有替用户授予无障碍或通知读取权限。
- `git diff --check` 通过。

没有使用真实支付账户完成扣款；合成样本和模拟器不能证明所有真实美团/抖音版本已覆盖。

真机验收应重点检查：

1. 微信/支付宝各一笔正常付款、收款，确认金额方向；通知栏与应用待确认状态分别核对。
2. 美团/美团外卖/抖音/极速版的支付结果页，在有通知和无通知两种情况下各核对一次。
3. 同笔支付经过平台和付款工具两个应用，核对合并/疑似提示；连续两笔同额支付必须都能保留。
4. 部分退款、二次同额退款、取消支付、优惠券到账、订单历史、聊天支付文字均做反例。
5. 关闭应用提醒仍能入库；关闭应用捕获开关后停止；后台清理、重启、ColorOS 电池限制与权限撤销能在设置页准确呈现。
6. WebView、自绘、受敏感信息保护、隐藏金额或未暴露文字的页面，确认不会伪造金额；必要时手记。

当前没有加入后台截图/OCR、读取短信、自动点击支付流程、导入历史账单、自动确认记账。对不可访问的页面，不承诺“全自动不漏记”；可以后续基于用户提供的脱敏凭证样本继续适配。

参考 Android 官方接口：[NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService)、[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。通知查询应在服务连接后进行；页面读取需要声明窗口读取能力并由用户开启。应用及系统仍可限制可访问内容。
