# 微信好友转账收款适配（v0.5.5）

日期：2026-10-24，北京时间。验证对象为 RMX3888 / Android 16 / 微信 8.0.78。

`0.5.5+13` 最终修复包已沿用原正式签名覆盖安装，未卸载、清空账本或更改权限／模型设置；本轮没有发布 GitHub Release。

## 漏记原因

付款结果页使用 `UIPageFragmentActivity`，本次收款结果页使用 `com.tencent.mm.plugin.remittance.ui.RemittanceDetailUI`。两者的无障碍树均可能只有一个隐藏空根节点。原空节点适配器仅处理前者，要求“支付成功、待收款人确认、金额、完成”四个付款锚点，不能处理本人确认收款后的页面。

本次实际收款页显示“你已收款，资金已存入零钱”、5 元金额、零钱余额入口、转账时间及收款时间。底部“账单详情”是导航入口，不能把其存在等同于正在浏览历史账单；也不能全局取消对历史详情页的过滤。

## 实现与边界

- 将该 Activity 接入已有的按窗口截图、本地中文 OCR、代际校验、独立截图授权和尝试限流；其他空页面不能据包名直接进入此适配器。
- 按收款场景验证本人完成状态、独立金额及有标签的转账时间和收款时间。可读节点与空节点 OCR 共用同一交易语义。
- OCR 金额仅在已定位区域允许人民币符号缺失或拆分后的两位小数；不补数字、不猜数字，也不接受多个金额或外币。
- 实机 ML Kit 返回“你已收款,资金已入零钱”“零线余额”“账单详惰”和无人民币符号的 `5.00`。完成状态允许具有同样完成语义的“已入零钱”；两个非财务导航标签仅在对应区域处理这两个实际观测到的 OCR 别名。金额和日期不作字符替换；保存的状态依据保留实际 OCR 原文，不补回未读到的“存”。底部导航链接漏读时不影响其他完整凭证的判断。
- 本人收款为 `INCOME / transfer_received`，但转账用途未知，继续保存为待核对资金变动，不自动当作经营收入或消费退款。
- 账目采用实际收款时间，捕获证据单独保留观察时间。不把时间或金额拼成伪订单号，不据此跨来源静默合并。
- 收款时间不得晚于观察时间，转账时间不得晚于收款时间；只自动补采最近 30 分钟的此类收款页。更早的历史交易使用账单导入或主动补录。
- 同窗口同页重绘沿用会话身份；不同收款时间可形成新的同额交易。同秒且无其他区别的凭证、跨进程重新进入和跨来源关联仍需更强交易标识，不能声称已解决所有重复或吞单情形。
- 新页面事件会重置有界重读流程，并允许截图限流窗口恢复后补读，避免在待确认页面用尽次数后丢失随后完成的收款。

## 场景覆盖分层

| 场景 | 自动化证据 | 真机范围 |
| --- | --- | --- |
| 微信发起转账，收款方未确认 | 四锚点、资金方向、入库、同额及重绘回归 | 微信 8.0.78 的既有付款页，见 [付款验证](wechat-opaque-transfer.md) |
| 微信本人确认收款 | 完成状态、金额、两类时间、入库、独立同额及重绘回归 | 本文所列收款页 |
| 待确认后再收款 | 未完成不入库；次数用尽后的确认仍有补读 | 自动化事件序列；本轮没有发起新的真实付款 |
| 微信收款码／支付宝到账 | 通知和通用结果页解析回归 | 本轮没有实测新的到账通知 |
| 商户消费、美团／外卖、抖音／极速版 | 六个包名、实付与优惠、方向、通知来源过滤回归 | 不代表所有平台页面已通过真机验收 |
| 红包、退款／部分退款 | 完成／未完成、方向及退款身份边界回归 | 本轮未进行真实红包或退款 |
| 历史页面、输入／密码、聊天、失败、歧义金额 | 本地拒绝及服务到数据库回归 | 不能靠放松完成状态扩大覆盖 |
| 字体／横屏／其他微信版本、双开、锁屏和长时后台 | 既有权限和读取边界测试 | 仍需逐项设备验证 |

截图和真实 OCR 仅作本机临时诊断，不加入仓库、备份或云端。回归使用脱敏合成 OCR 行；测试数量不等同于真实支付覆盖率。
