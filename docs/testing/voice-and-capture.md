本文保留 v0.4.2 的验证记录；v0.5.0 已增加视觉补充、模型推断和语音直接生成草稿，当前范围见 [识别系统验证](recognition-system.md)。

日期：2026-10-24（北京时间）。本轮按用户选择完成自动化验证；不以合成页面、框架模拟或模拟 HTTP 响应宣称微信真机或真实云服务已验收。

## 问题与修复

### 语音录入

此前 Android 的语音命令交给系统 `SpeechRecognizer`；没有安装可用识别服务的手机，即使允许麦克风也无法使用。当前 Flutter 主应用在两端使用独立的麦克风录音与云端转写服务。

- 「设置 → 语音模型」及一句话录入页均可进入配置。服务地址、模型和 API Key 独立于聊天模型。
- 预填 Qwen 中国内地端点和 `qwen3-asr-flash`；另支持兼容 `/audio/transcriptions` 的服务。用户须填写与端点地区、模型权限匹配的密钥。
- 录音采用内存中的 16 kHz、单声道 PCM/WAV，最多 60 秒；结束录音后上传，转写请求限时 45 秒。支持取消，取消后不接收旧请求的迟到结果。
- 设置页可保存后进行真实录音测试，返回转写文字，不调用账单解析或写入账本。一句话录入的转写结果仍需点击「识别账单」并核对保存。
- 拒绝不安全的服务地址和跳转；限制音频、响应、转写文本大小；错误不回显服务返回的密钥或音频。
- 配置与密钥原子保存在设备安全存储中，密钥不会进入快照、账本备份或 Android 自动备份。更换服务来源时需重新填写密钥，留空不能把已有密钥发送到另一个来源。

### 没有支付通知的微信转账

通知监听无法捕获从未发布的通知。此场景由页面采集提供第二条入口：

`应用内开启页面读取 + 系统无障碍授权 + 服务已连接 → 页面事件/稳定页读取 → 本地凭证解析 → 去重 → 待确认账单`

代码确认的问题及修复：

1. 系统无障碍授权和应用内页面读取开关相互独立，应用内开关默认关闭。设置页首屏新增无通知转账状态与操作入口，明确缺的是哪一个条件，不自动替用户开启。
2. 原先窗口事件后仅延迟 350 ms 读取一次，节点暂不可读或页面迟到会漏识别。现在先即时读取，失败后按 250/750/1500 ms 间隔有界补读；新事件立即唤醒采样，不被旧页面等待挡住。
3. 连接服务或开启开关时也采样当前稳定页面；兼容窗口变化事件和未定义窗口编号。仅取活动/聚焦应用窗口，并核对包名与有效窗口编号。
4. 支持明确的「转账成功」「已转账」「转账已完成」凭证及付款方「待对方收款」说明；收款方确认状态不把已经完成的支出反转成收入。单独「待对方收款」没有完成证据仍不接受。
5. 同时读取可见节点的文字与内容描述；拒绝输入框、密码、不可完整读取的页面。不截图、不点击、不把页面全文交给云端。
6. 输入页会更新支付页面会话，独立的第二笔同额支付不会一直被旧会话吞掉；商户、单号晚加载则不会被当成一笔新交易。不同可靠订单仍可分别记录。
7. 页面诊断记录最近事件时间、读取时间、应用和处理结果，不保存页面全文。诊断事件在 Flutter 桥接处合并，避免每次界面重绘都刷新整个账本。

## 尚未验证与不能保证的场景

- 本轮 ADB 没有连接手机；用户选择先完成自动化测试。尚未验证用户所用微信版本的真实节点树、ColorOS 后台限制、锁屏/息屏、自启动、系统回收、重启后的实际恢复。
- 未使用用户真实 API Key 发起云端转写，也未验证真实麦克风音质、方言、噪声、蓝牙耳机、电话抢占。自动化通过不代表该账号有余额或模型权限。
- 自绘、受系统敏感信息保护、隐藏金额或不暴露无障碍节点的结果页可能不可读取。页面读取不是屏幕 OCR，也不保证每个应用版本所有支付都被捕获。
- 聊天中的历史转账卡片、账单历史/详情页不会作为新交易自动入账，以免翻看旧记录生成新账。没有可读完成凭证时应手动或语音补记。
- 没有订单号时，重新进入同一结果页或进程重启不能总是证明两次采集是否同一笔；现有弱证据策略保留疑似记录供用户确认，不按金额永久吞掉后续支付。
- 未穷尽所有支付 App/系统版本和语言。后续真机验收应按本矩阵重放用户真实场景，并用新增诊断定位未覆盖的节点或状态。

接口依据：[Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[Qwen ASR API](https://docs.modelstudio.console.alibabacloud.com/zh/model-studio/qwen-asr-api-reference)。

## 2026-10-24：清理后台后的无障碍授权状态

用户反馈：朋友的小米手机开启无障碍后，清理后台再打开应用，又显示等待授权。尚未取得该手机的型号、系统版本或清理前后的系统设置记录，不能据此确认系统是否真正撤销了授权。

已确认的代码问题：此前以 `getEnabledAccessibilityServiceList` 判断授权，而 Android 15 AOSP 的该接口读取已绑定服务列表。服务被终止或尚未重连时，列表可能不包含 PennyPilot，但系统仍保留用户授权。参见 [AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/services/accessibility/java/com/android/server/accessibility/AccessibilityManagerService.java#L1248)。

本次修复：

- 共享 `PaymentAccessibilityPermission` 优先精确匹配系统保存的无障碍服务组件，区分授权与进程内服务连接状态；支持完整和缩写组件名。系统设置为空或已移除本应用时显示未授权；仅在无法读取该设置时使用系统服务列表作为备用依据。
- Flutter 宿主与旧 Compose 入口使用同一授权判断。已授权但未连接时先刷新状态，提供自启动与后台设置入口，服务连接后更新为就绪。
- 自动采集页与权限引导补充小米、realme 的后台设置说明。电池优化豁免不等于已允许自启动，也不证明一键清理会保留应用。
- 无障碍授权和服务绑定仍由系统管理；本次没有实现厂商清理后的强制重启或自动重新授权。
