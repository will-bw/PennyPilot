# 微信空节点转账成功页验证（v0.5.1）

日期：2026-10-24，北京时间。修复包 `0.5.1+9` 已使用现有正式签名覆盖安装到用户手机；未卸载或重置账本，未发布到 GitHub。

该本地验证包未单独对外发布；微信修复与后续百炼语音修复合并为 `0.5.2+10` 正式版本。下文保留微信修复当时的版本、测试数量和实机证据。

## 真机问题与证据

- 设备 RMX3888，Android 16 / API 36，微信 8.0.78，显示尺寸 1264 × 2780。
- 用户在约 13:07 自行完成的 3 元转账，画面包含“支付成功”“待〈收款人〉确认收款”、金额及底部“完成”。
- 前台 Activity 为 `com.tencent.mm.framework.app.UIPageFragmentActivity`。PennyPilot 原服务与独立 `uiautomator dump` 都只得到一个无文字、无可见区域、无子节点的根节点。服务计数为 visited=1、hidden=1、text=0，输入、密码、缺失子节点和外包节点均为 0。
- 原代码在 `snapshot.text == null` 时直接结束，后续视觉候选仍依赖节点文字。因此既无法规则解析，也不会启动 OCR；此前模型配置和转账关键词修改没有解决这个采集缺口。

## 修复行为

1. 保留原节点读取和输入、密码、不完整页面的拒绝逻辑。仅对上述微信 Activity、精确的单隐藏空根快照开启新适配器；Activity 本身不能证明付款成功。
2. 用户必须独立启用“本地支付截图补充”。本次手机上该开关已经启用，无须修改原设置。使用 Android 14+ 的 `takeScreenshotOfWindow` 获取目标窗口，失败时不退回全屏截图。窗口、页面事件代际、账本代际或授权改变时丢弃旧帧。
3. 使用随包中文 OCR，不依赖云模型。要求四个锚点及其上下位置、居中区域均符合已观察布局：顶部“支付成功”、收款人待确认状态、独立金额、中下部“完成”。除系统栏外出现其他页面文字、多个金额、缺失几何信息或任何锚点不完整时拒绝。
4. 真机 OCR 实际将金额行读取为 `3.00`，遗漏了单独绘制的人民币符号。只有在此场景的专用金额区域才接受没有货币符号的两位小数；整数、负数、错误千分位、外币、字母和不完整小数不作数字替换或截断。正常带人民币符号和分离的货币符号仍受金额校验。
5. 识别输出为本人 `EXPENSE` / `transfer_sent`，用途为 `unknown`，保持 `PENDING`，即使用户已开启可信支付自动入账也不自行认定消费或互转。字段依据保留本地 OCR 提取的金额、本人付款完成状态和收款人状态，整张图片和 OCR 全文不持久化、不上传。
6. 接入既有会话与原子写入。同页重开和重绘不新增；进入新的 `RemittanceUI` 转账流程会划定新交易边界，允许同窗口、同额第二笔。截图和 OCR 的尝试受间隔、次数及窗口数量限制。
7. 对页面读取开关使用 `distinctUntilChanged`，避免 DataStore 中其他设置变化也取消任务、清空事件。ADB 服务诊断仅输出状态、计数、锚点位置和时间，不输出截图、OCR 正文、姓名或金额。
