# 微信完成页读取回归（v0.4.3）

日期：2026-10-24。用户在 v0.4.2 真机反馈：微信出现“转账成功/已转账”页面，需要点击完成或返回；PennyPilot 已收到微信页面事件并读取，诊断为“已跳过输入或受保护页面”，当日捕获 0 笔。

## 证据与定位边界

截图只显示 PennyPilot 的诊断结果，没有微信的无障碍节点树。原实现对所有 `Snapshot.text == null` 都报 `protected`：除输入和密码外，也包括空树、缺失子节点、节点数量/层级/文本上限。因此不能据此声称微信屏蔽了页面，也不能确定此次真机命中了哪一个分支。本轮 ADB 没有连接手机。

源码中确定存在以下问题，本次均针对性修复：

- 在包名过滤之前检查输入属性，其他应用的输入节点也会拒绝整页。
- 不可见容器直接终止遍历，即使其后代可见也读不到凭证。
- 原始 250 节点预算混合了隐藏、其他应用与有效节点；包含更多装饰节点的完整结果页会被截断拒绝。
- 补读仍可能反复获取系统缓存中的同一棵旧树；原补读窗口总长 2.5 秒。
- 不同失败原因被合并，无法据截图区分下一步修复路径。

## 修复行为

1. 先核对节点所属应用，其他应用节点不会触发输入页判定；隐藏普通容器继续有界遍历可见后代。输入和密码内容始终不读取。
2. 总遍历上限 2,000 节点，可见有效节点上限 1,000，最大层级 60；依旧限制 12,000 字符。超限或持续缺失节点时拒绝整页，不解析截断文字。
3. 补读时间点为 0、250、1,000、2,500、5,000 ms；新页面事件会唤醒等待。Android 13 及以上在补读前清理本服务节点缓存，再取当前窗口。旧系统保留有界重新读取。
4. 区分输入、密码、缺失树、结构超限、文本超限和空文本状态；仅输出节点数量，不保存页面正文或输入内容。
5. 保留同应用可见输入框的整页拦截。不能因为输入为空、未聚焦或没有键盘，就把聊天里的旧转账文案当成新支付。
6. 在内存中保留最近 8 条不同识别状态，相邻重复状态合并；解析中间态不挤占历史。用户从微信完成页返回聊天后，仍能查看先前完成页的结果；不写入账本备份，不持久化页面正文。

## 回归范围

- 稳定微信完成页、不可见容器下的可见完成页、其他应用输入节点、超过旧 250 节点预算的完整结果页均经过服务事件 → 读取 → 解析 → Room 持久化验证。
- 缓存旧树恢复、没有第二次事件的延迟完成页、缺失子节点恢复、同页去重和连续同额转账。
- 失败状态位于原 250 节点预算之后、聊天输入、密码、真正超限和持续不完整树不得入账。
- Flutter 诊断覆盖六类状态、可选计数、旧快照兼容，以及窄屏大字、横屏深色、平板布局。
- 诊断过程保留先前结果、合并连续重绘、最多 8 条，未知或非法 UI 字段不展示。
