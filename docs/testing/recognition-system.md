# 识别系统验证 — v0.5.0

日期：2026-10-24。测试使用合成支付节点、事件序列、HTTP 服务替身及本地测试数据库。用户选择先完成自动化测试，手机更新后再验证真实微信和模型账号；自动化数量不代表真机覆盖率。

后续 v0.5.1 已完成微信 8.0.78 空节点付款成功页的指定真机验收，详见 [微信空节点转账页验证](wechat-opaque-transfer.md)。下文保留 v0.5.0 时的测试结果与边界。

## 已实现的链路

- 无通知微信转账：无障碍窗口事件 → 完整只读节点和会话 → 成功状态、本人资金方向与金额 → 规则候选 → 原子去重 → 待确认。包括只有“转账成功／已转账、金额、完成”的结果页；“对方已收钱”不把本人付款反转为收入。
- 页面字段迟到：有界补读至 5 秒，同会话后到订单号补充证据；人工编辑和确认结果保留。输入页开启下一笔会话，快速连续同额付款保留两笔。
- 本地视觉补充：用户独立启用后，对安全支付区域截取、裁剪并运行随包中文 OCR。受保护、无法确定区域和过期画面停止处理。截图/OCR期间的页面事件变化使旧帧失效。
- 未知安全支付页：用户开启页面云识别后，有限文字和可用结构加密排队，由所选模型提议。金额、方向、完成状态须有本地可核对证据；未验证模型路径只产生待确认候选。
- 主动文字／语音／图片：统一候选协议，关键字段依据、用途、日期和问题可查看。语音结束即转写并生成草稿；图片由用户选择或分享。普通明确输入可单独启用自动保存，图片、复杂拆分与歧义需要确认。
- 账单补漏：本地读取微信、支付宝 CSV，按账户与交易标识展示新增、重复、冲突和待核对行；未完成或无法解释的行明确列出，不猜测补值。
- 可靠写入：稳定操作身份、证据版本、账目编辑版本、删除标记和持久账本代际共同拦截重复与迟到结果。恢复备份清理旧模型任务。退款抵减支出，互转、借还款和未知用途不直接计消费收入。

## 真机验收

1. 覆盖安装新版本，确认原有账本还在。在“自动采集与权限”确认页面读取开关、无障碍授权和服务连接三者均正常。
2. 先关闭云端与视觉补充，用微信完成一笔小额转账，在“转账成功／已转账”页停留片刻。返回 PennyPilot，检查金额、资金流向、时间及待确认状态；选择实际用途再确认。
3. 测试待对方收款与对方已收款；经输入页再完成一笔同额转账；返回查看历史详情应不新增账目。不要为了测试反复向不相关的人付款。
4. 如果仍未识别，先读最近诊断；在诊断页启动一次样本，再进行下一次实际支付。返回预览样本，删除姓名等不希望提供的信息，再复制给开发者。诊断样本保留十分钟，普通运行记录不保存全文。
5. 配置文字模型，先用“测试文字识别”验证 12 元午饭；语音模型单独测试转写，再在录入页说“今天午饭十二元，打车二十八元”，核对两笔后保存。
6. 按需开启本地视觉补充、页面云识别与云图片识别。选择真实支持图片的视觉/复核模型，用主动图片测试验证账号能力。开关不代表远端账号权限和额度有效。
7. 检查弱网、切后台和返回后的结果；删除一笔测试记录后重复请求不应恢复它。对照导出的原始账单检查有无漏记与重复。

## 能力边界

- 尚未取得用户手机当前微信版本的真实节点回放；ColorOS 等系统的后台限制、双开与工作资料、锁屏和重启仍需设备验收。系统授权不能保证应用始终运行。
- 受保护或完全不可观察的页面没有可验证付款事实时停止自动写入。自动视觉补充也不能绕过截图保护；本地文字/OCR完全没有可核对金额时不能承诺由后台视觉模型恢复。可主动分享图片生成待核对候选或导入账单。
- 后台云请求只发授权的安全支付候选；本地交易标识保留用于关联，文本/结构中的标识做临时替换。主动分享的图片可能包含凭证上的个人信息，上传前由用户自行选择和裁剪。
- 当前账本以人民币分计价；外币、未知 CSV 格式、账户不明的复杂业务关系不自动猜测。退款和借还款可分开记录、选择用途，但自动关联与结清需要明确证据或人工确认。
- 模型与语音网络测试使用可控响应，未使用用户真实密钥和付费接口；真实服务的权限、余额、方言和音质由设置页能力测试与手机验收确认。
- 规则随签名 APK 固定发布；新支付版本的覆盖须增加样本回归后确认，不能宣称支持所有支付应用、版本和场景。
