# 主动输入时间处理验证（v0.5.3）

日期：2026-10-24，北京时间。对应版本 `0.5.3+11`；本文记录该版本的自动化验证、真机结果与证据边界。

## 反馈与证据边界

用户手机 RMX3888 / Android 16 / PennyPilot 0.5.2 在“一句话”记账中输入“今天中午吃的饺子花了20块钱。”，显示“第1笔的交易时间无效或在未来”。读取手机时已经是 13:55，当地时区为 Asia/Shanghai，设备时间没有异常。

原失败请求没有保留模型返回，不能确认当时是错误格式、错误时区还是模型生成了未来时分。使用相同校验逻辑的临时时间诊断包，在 13:59 用原句和原 ChatGPT 配置重新请求时通过校验，遵循用户已开启的主动输入自动保存设置保存一条 20 元餐饮支出；因此不能把该次重试成功归因于后续修复，也不能宣称稳定复现了原失败。

源码可确认两个缺口：发送给模型的本地 ISO 时间没有 UTC 偏移；校验器只接受精确到时分的时间，拒绝有效的单独日期，并把格式／日期非法与实际未来时间合为同一提示。

## 改动与自动化验证

- 识别提示包含设备当地 ISO 时间和 UTC 偏移；只有明确时分才要求精确时间，“今天中午”等时段返回 `YYYY-MM-DD` 和 day 精度。
- 仅在识别候选入口允许单独日期，通过同一严格日历校验，按本地日期解析，精度固定为 day；模型标成 exact 也不会把日期当作精确时间。CSV 调用默认仍要求完整时间。
- 金额、资金方向、完成状态及原文日期一致性校验保持生效；非法日期与未来时间使用不同提示。
- 临时时间日志和构建开关已移除，最终 APK 不记录模型返回或用户输入。

完整 Flutter 回归在 `TZ=Asia/Shanghai` 下执行：345 项通过；`./tool/flutterw analyze` 无问题。新增回归覆盖原句的日期候选、非法／未来日期、原文日期冲突、日期精度、图片按日候选、原生 ChatGPT 传输进入统一校验、明确时区提示和 CSV 时间要求。

`./tool/flutterw build apk --release` 成功；`python tool/prepare_release.py` 校验应用 ID、版本 0.5.3 (11)、非调试构建和既有正式签名证书成功。未修改原生识别或数据库代码。

## 最终包真机复核

- 使用既有正式签名覆盖安装 0.5.3 (11)，账本和 ChatGPT 配置保留。
- 临时关闭主动输入自动保存，用同一原句发起真实 ChatGPT 识别；14:04 返回一笔有效草稿，界面为 10 月 24 日、餐饮、消费支出、20.00 元、备注饺子，没有时间错误或补充问题。
- 该复核草稿已移除，不再次保存；随后恢复原来的主动输入自动保存开关。账本保留前述重试成功时保存的唯一一笔 20 元餐饮记录。
- 这证明最终包在本机使用该模型配置和原句成功生成候选，不证明原失败返回的确切原因，也不代表所有模型和日期表达均已通过真机验证。
