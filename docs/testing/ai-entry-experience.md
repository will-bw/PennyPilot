# AI 记账体验调整

日期：2026-11-01。对应分支 `codex/ai-bookkeeping-experience`。

## 用户任务与行为

| 输入或操作 | 预期行为 |
| --- | --- |
| 昨天晚上 7 点过吃的盖饭，17 块钱 | 自动记下昨天约 19:00 的 17 元餐饮支出，不追问年份或支付完成声明；显示实际结果并可撤销 |
| 10 月 30 号午饭 17 元 | 补全最近已经发生的年份；跨年补录可使用上一年 |
| 午饭 17 元 | 按今天记录，推荐已有分类，不索取商户、账户或具体时分 |
| 前几天吃饭 17 元 | 结合当前时间推断日期，保留近似说明并自动保存，不为约略日期反复追问 |
| 只说了盖饭和地铁，缺地铁金额 | 已明确的盖饭先记，保留原描述和地铁问题，补一句“地铁 4 元”后继续记，不要求再确认盖饭 |
| 部分账单已保存后继续补充 | 保留原文和未解决的问题，已经保存或手动修改的同次记录不重复生成 |
| 切换一句话和手动 | 两种模式已填写的内容保留，编辑已有账单直接打开表单 |
| 问账里说“午饭 17 元” | 推断并自动新增，可在同一轮继续查询刚记下的账本；返回真实 ID，界面提供撤销 |
| 本月尚未结束时查看统计 | 上月显示整月支出，不将本月至今与上月整月计算环比百分比 |
| Android 捕获成功支付 | 根据场景、商户、历史和用户更正自动推断分类、用途及账户；授权 AI 后可异步完善同一账单 |
| 真实转账未提供用途 | 自动记录资金转移，不冒充消费或收入，也不强制逐笔追问用途 |
| 自动结果被用户修改 | 学习明确更正的分类、用途及账户，后续同商户优先沿用；暂定转移不固化为稳定习惯 |
| 自动记账后点撤销 | 只撤销本次未被人工编辑的记录，保留其他账单；旧捕获与补充结果不能恢复已撤销记录 |

金额必须有原文依据。明确失败、未支付、未来计划、金额冲突或无法判断的借还款用途仍需要处理；这些情况与省略年份、分类、商户等可合理补全的信息分别对待。图片仍按所选凭证提取，不把无成功依据的支付凭证当作已完成消费。

## 自动记账链路整合

第二轮将默认行为从“先生成草稿”改为“推断后自动保存，结果可撤销”。尊重显式关闭自动保存的选择，数据类型授权不随自动保存开关改变。

- 主动输入逐笔保存：约略时间、中文日期、方向推断、分类、退款和可守恒拆分均可自动记录；另一笔缺金额不会阻断明确项。撤销后继续补充不会恢复已撤销记录。
- 问账新增：真实用户请求经同一识别协议校验后自动写入，返回实际 ID 和 `applied`，刷新同轮查询快照；重复调用不重复保存。后续模型失败仍保留已成功记录的撤销凭据。关闭自动保存、修改、删除和预算变更保留核对流程。
- 后台捕获：本地成功后仍可持久排队进行获授权的语义推断。模型使用真实分类和少量同商户历史、明确更正偏好，填入用途、分类、账户与备注，不再被强制清成未知。相同事件原子完善同一账单。
- 更正学习：用户编辑自动结果后保存分类、用途和账户偏好；临时转移占位不污染稳定习惯，当前退款事实不被历史收入偏好覆盖，模型可结合本次上下文改变过去商户习惯。
- 纠错：主动输入和问账共享撤销凭据；后台通知显示撤销、修改。撤销绑定本轮 ID、事件身份、账本代次及未人工修改的版本，保护其他记录并写入防重建标记。
